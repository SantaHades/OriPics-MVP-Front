## 1. 대표 원안 — 이해한 내용 (전달 확인용)

아래가 제가 이해한 원안입니다. 틀린 부분이 있으면 표시해 주세요.

1. 회원가입 시 모든 회원에게 숫자 파트너코드가 자동 부여된다. 대표 1234, 이후 가입자 1235, 1236 … 제휴사는 123부터 수동.
2. 신규 가입자가 가입 폼에서 파트너코드 입력 → [확인] → 코드 주인 이름 표시 + 확인 버튼 비활성(잠금).
3. 가입 완료 시 신규 가입자 화면에 **자기 파트너코드**가 표시되고 **50% 할인권 1장**을 받는다. 코드 없이 가입하면 못 받는다.
4. 입력된 코드의 주인도 **50% 할인권 1장**을 받는다.
5. 신규 가입자 A가 자기 코드를 지인 B에게 주고 B가 가입하면 A는 또 1장. 이 상태(2장)에서 A가 Pro로 올리면 **첫 달 0원**.
6. **두 번째 결제부터는 1장만** 적용. 여러 명이 가입해도 쌓아두고 매달 1장씩.
7. 12명 가입 시 6개월 무료. 결과: 첫 달 무료 → 11개월 50% → 6개월 무료 (총 18개월).

전달은 정확히 됐습니다. 아래는 이 원안을 실제로 운영·구현하려면 채워야 하는 빈칸입니다.

## 2. 원안 검토 — 빈틈·모순 9가지

| # | 문제 | 제안 |
|---|---|---|
| 1 | **헤드라인 vs 본문 불일치** — "지인이 **프로플랜으로 가입**할 때마다 50%"인데 본문은 **회원가입**만으로 지급 | 본문(회원가입 기준) 채택 권장. 헤드라인을 "지인이 내 코드로 **가입**할 때마다"로 수정. Pro 결제 기준으로 하면 파트너 동기가 약해지고 릴레이가 끊김. 대신 어뷰즈는 §6으로 막음 |
| 2 | **가입 폼이 없는 경로** — 소셜 로그인(Google·Apple·Kakao·Naver)은 첫 로그인 시 계정이 자동 생성되고, 앱은 소셜 로그인만 가능. "가입 시 입력"만 있으면 소셜·앱 가입자는 전부 배제됨 | **가입 후 7일 이내 1회 입력** 경로 추가: 첫 로그인 직후 환영 화면 + 프로필 파트너 카드에서 입력. 이메일 가입 폼에는 원안대로 입력란 유지 |
| 3 | **기존 회원(베타 테스터·이미 가입한 사람)** 은 "가입 시 입력"이 불가능 | 기존 회원도 챌린지 기간 중 **1회 입력 가능**(가입 7일 규칙 대신 "챌린지 기간 내 1회"). 입력하면 양쪽 1장. 안 하면 코드만 부여되어 초대는 가능 |
| 4 | **"선착순 500명 파트너"의 정의** — 모든 회원이 코드를 받으면 누가 500명인가? | **파트너 = 코드를 입력해 챌린지에 참여한 회원**, 참여 순서 500명까지. 501번째부터는 코드 입력 시 **본인 할인권 1장은 받지만** 자기 코드로 초대해도 적립 없음(=릴레이 종료 지점). 랜딩에 "파트너 잔여 N명" 카운터 표시 |
| 5 | **0원 결제** — PortOne·KG 빌링키 청구에 0원은 없음. 카드 미등록 상태로 "첫 달 무료"를 주면 카드 없이 Pro 쓰고 이탈 | 첫 달 0원도 **빌링키(카드) 등록 필수**. 서버는 청구를 건너뛰고 30일 주기만 부여, 다음 달부터 청구. 결제 완료 화면·이메일에 "다음 결제 ₩4,950 / 10월 10일" 명시 |
| 6 | **금액 고정 검증이 깨짐** — 현재 코드는 결제 금액이 9,900이 아니면 `amount_mismatch`로 거절하고, customData 누락 시 금액으로 플랜을 역추론함(`planFromAmount`) | 청구 시점에 **기대 금액(9,900/4,950/0)을 paymentId 단위로 저장**하고 webhook·complete는 저장값과 비교. 역추론은 4,950도 pro_monthly로 인식하도록 수정 |
| 7 | **유효기간 없음** — 무기한 적립은 회계·약관 부담, "적립" 성격 논란(A-79 이월 금지 결정과 같은 맥락) | 할인권·무료 이용권 모두 **발급일 +24개월**(12명 시나리오 18개월 커버). 현금 환급·양도·타 상품(원데이 패스·Business·연간) 적용 불가. 표현은 "할인권/이용권"만, "적립·포인트·충전" 금지 |
| 8 | **순번 코드는 추측 가능** — 1234, 1235 … 를 아무나 입력해 남의 코드로 혜택을 받고, 코드 주인 이름이 그대로 노출됨(1235~9999 훑으면 회원 이름 수집 가능) | 순번 유지는 대표 의도(공유 쉬움)로 존중. 대신 ① 이름은 **마스킹**(손*석) ② 조회 API 분당 5회·일 20회 제한(기존 `RateLimit` 재사용) ③ 대표 코드 1234가 공개돼 "사실상 전원 할인권"이 되는 점은 **의도된 진입 유도**로 수용(§10 Q4) |
| 9 | **앱스토어 규정** — 앱에서 "웹에서 결제하면 50% 할인" 식 문구는 App Store 3.1.1/3.1.3 위반 소지(U-35 결정: 앱은 결제·웹 결제 유도 없음) | 앱에는 **내 코드 표시·복사·공유·코드 입력**만. 할인 금액·결제 문구는 웹 랜딩/프로필에만. 공유 문구는 앱에서도 "가입 링크"까지만 |

추가 소소한 빈칸: 12명 보너스 반복 여부(24명?), 환불 시 할인권 복원, 해지 후 재구독 시 잔여 할인권 유지, 파트너코드 주인이 탈퇴한 경우 입력 불가 처리, 무료 Pro 테스터 계정의 할인권(결제 없으니 보관만).

## 3. 확정 규칙 (v0.2)

### 3.1 파트너코드
- 4자리 이상 숫자 문자열. `User.partnerCode` unique. DB 시퀀스 `1235`부터. 대표 계정 = `1234` 수동. `100`~`999`는 제휴사용 예약(어드민 수동 부여, 시퀀스 미사용). **제휴사 코드 계정은 파트너 500명 카운트에 포함하지 않음**(별도 계약 혜택, Q12).
- 대표 코드 1234는 랜딩·공유 문구에 노출 가능. 누구나 1234로 가입해 할인권을 받는 상황은 **의도된 진입 유도로 수용**(Q4).
- 기존 회원 백필: 가입일(createdAt) 순으로 1235부터 부여. 대표 계정만 1234.
- 코드 조회: `GET /api/partner/lookup?code=1235` → `{ ok, ownerNameMasked: "손*석", available }`. 없는 코드·본인 코드·탈퇴 계정은 실패 문구. 레이트리밋.

### 3.2 참여(코드 입력) 조건
| 대상 | 입력 가능 시점 | 횟수 |
|---|---|---|
| 이메일 가입 | 가입 폼(원안) 또는 가입 후 7일 | 1회 |
| 소셜 가입(웹·앱) | 첫 로그인 환영 화면 또는 프로필, 가입 후 7일 | 1회 |
| 기존 회원(챌린지 공지 전 가입) | 챌린지 기간 중 언제나 | 1회 |
- 입력 후 잠금(수정·삭제 불가). 자기 코드 입력 불가. 순환(A→B, B→A) 허용하지 않음 — B가 A 코드로 가입했으면 A는 B 코드 입력 불가.
- **참여 확정 시점 = 이메일 인증 완료된 계정이 코드를 입력·확인한 시각**. 이 시각 순서로 파트너 500명 카운트(Q5). 501번째부터는 본인 할인권 1장만 지급, 자기 코드로 초대해도 적립 없음.
- 기존 회원(베타 테스터 포함) 1회 입력 허용(Q10). 무료 Pro 테스터 계정은 할인권을 보관만 하고 유료 전환 시 적용.

### 3.3 혜택
| 종류 | 대상 | 조건 | 수량 |
|---|---|---|---|
| 50% 할인권 (₩4,950) | 코드 입력자 | 참여 확정 시 | 1장 |
| 50% 할인권 (₩4,950) | 코드 주인 | 입력자의 참여 확정 시. 단 코드 주인이 **파트너(500명 내)** 일 때만 | 1장/명, 상한 없음 |
| 1개월 무료 이용권 6장 (6개월 연속 자동 적용) | 코드 주인 | **유효 초대 12명** 달성(유효 = 이메일 인증 + 첫 인증 1건 완료 계정, Q2), **운영자 검수 후 24시간 내 지급**(Q3) | **계정당 1회 한정**, 24명 반복 없음(Q9) |

- 발급일 +24개월 유효. 현금 환급·양도 불가. `pro_monthly`에만 적용(원데이 패스·연간·Business 제외)(Q6).
- **파트너 500명 마감 후에도** 파트너(500명 내)의 코드로 가입이 일어나면 파트너에게 1장씩 계속 적립(상한 없음, 12명 보너스 포함). 적립 종료 시점은 **2026-12-31 23:59 KST**. 이후 가입은 양쪽 모두 미지급, 기발급 혜택은 24개월 유효기간까지 사용 가능(9/10 대표 확인).
- 부정 참여 판정 시 미사용 혜택 회수, 이미 사용분은 회수하지 않음(약관 명시).

- 크레딧 지급·주기(30일)·이월 없음 규칙은 정가 결제와 동일. 0원 갱신도 정액 1,000 리셋.

### 3.5 12명 시나리오 검산 (원안 그대로 성립)
| 월 | 보유 할인권 | 결제 | 비고 |
|---|---|---|---|
| 1 | 2장(본인 1 + 지인 1) | **₩0** | 2장 사용, 카드 등록 |
| 2~12 | 지인 11명 추가 → 11장 | **₩4,950 × 11** | 매달 1장 |
| 13~18 | 0장, 무료 이용권 6개월 | **₩0** | 12명 달성 보너스 |

### 4.2 이메일 가입 폼(원안)
이름·이메일·인증코드·비밀번호 + **파트너코드(선택)** [확인]. 확인 성공 → "손*석 님의 파트너코드" + 버튼 비활성·[변경] 작은 링크. 가입 완료 화면: "내 파트너코드 **1240** · 50% 할인권 1장 도착" + [코드 복사] [카카오톡/링크 공유] [나중에].

### 4.3 소셜 가입·앱 가입
첫 로그인 직후 1회 노출되는 환영 모달: "파트너코드가 있으신가요? (7일 이내 입력 가능)" [입력] [없어요]. 앱은 설정 탭 '파트너' 행에서 같은 입력(웹 API 호출). 앱 화면엔 금액 문구 없음(§2-9).

### 4.4 프로필 '파트너' 카드(웹) / 설정 탭 '파트너'(앱)
- 내 코드 크게 + [복사] [공유]. 공유 문구: "오리픽스에 제 파트너코드 1240으로 가입해 보세요 → https://www.ori.pics/ko/signup?ref=1240".
- 초대 현황: "가입 4명 / 12명" 진행바, 최근 가입 목록(이름 마스킹·일자).
- 혜택: "50% 할인권 5장(가장 빠른 만료 2028-09-10)", "무료 이용권 6개월(검수 중/사용 가능)".
- 다음 결제 예상: "10월 10일 ₩4,950 (할인권 1장 사용 예정)". 구독 카드(#subscription)에도 같은 문구.
- 사용 내역: 결제일·결제액·사용 혜택(할인권 n장/무료 이용권), 회수·만료 혜택은 사유와 함께 표시.
- 내 파트너 순번("파트너 128번째"). 파트너가 아니면(501번째 이후) "파트너 모집이 마감되어 초대 적립은 종료되었습니다. 할인권은 그대로 사용 가능합니다."

### 4.5 결제 화면
- `/billing/checkout`: 금액 줄이 "₩9,900 → **₩0** (할인권 2장)" 식으로 바뀜. 0원이면 "오늘은 결제되지 않고 카드만 등록됩니다. 다음 결제 10월 10일 ₩4,950" 고지 + 청약철회 문구는 결제액 0원에 맞게 조정.
- 지금 갱신하기 모달(A-79): 결제액을 할인 반영값으로 표시.

### 4.6 알림(이메일, nodemailer 기존)
- 코드 주인: "OOO 님이 회원님의 코드로 가입했어요. 50% 할인권 1장 (총 N장)".
- 12명 달성: "6개월 무료 이용권 검수 중, 24시간 내 지급" → 지급 완료.
- 정기 결제 D-3 예상 금액 메일은 **이번 범위 밖, 후속**(Q8). 대신 프로필·구독 카드에 다음 결제 예상액을 상시 표시.

## 7. 법·규정·약관 체크
- **표시광고**: "선착순 500명"은 잔여 카운터·마감 표시 필수. "펑펑"은 허용 범위, "무료"는 카드 등록·이후 유료 전환 조건을 같은 화면에 고지.
- **선불전자지급수단 논란 회피**: 무상 발행 할인권/이용권(현금 환급·양도·충전 없음)이라 해당 없음. 표현 규칙(§3.3) 준수. 회계는 매출 차감(할인)으로 처리.
- **제세공과금**: 자사 서비스 할인·이용권이라 경품(현물·현금)과 달리 원천징수 대상이 아니라고 보나, **세무 확인 1회 권장**(6개월 ₩59,400 상당).
- **개인정보**: 코드 주인 이름 마스킹 표시, 초대 현황도 마스킹. 개인정보처리방침에 "추천 관계(추천인·피추천인 계정 ID) 보관, 목적: 혜택 지급·부정 방지, 보관: 챌린지 종료 후 1년" 추가.
- **이용약관/이벤트 유의사항**: 혜택 조건·유효기간·회수 사유·결제 적용 순서·환불 시 처리·조기 마감·회사 사정 변경 고지. 약관 11조(환불) 산식에 "실결제액 기준" 한 줄 추가.
- **앱스토어**: 앱 내 금액·할인·웹 결제 유도 문구 금지(§2-9). 코드 표시·공유·입력은 무관.
- **PG(KG이니시스)**: 할인 결제 ₩4,950은 최소 결제금액 문제 없음. 0원은 청구 미발생(PG 무관).
- **시작 시점(Q11)**: 코드 부여·백필·참여 입력 기능은 배포 즉시 활성. 챌린지 **공지·랜딩 공개는 판매 개시(KG MID 게이트)와 동시**. 공지 전 참여자도 파트너 순번·혜택은 동일하게 인정.

## 8. 구현 개요

### 8.1 데이터 모델(Prisma)
```
User          + partnerCode String? @unique
              + firstChargeBonusUsedAt DateTime?  // 첫 결제 2장 혜택 계정당 1회(Q7)
              + partnerJoinedAt DateTime?   // 코드 입력·참여 확정 시각(500명 카운트 기준)
              + partnerRank Int?            // 1~500 파트너 순번, 501+ null
              + referredById String?        // 코드 주인
Referral      id, referrerId, refereeId(unique), status(pending|confirmed|revoked),
              confirmedAt, firstProofAt, riskFlags Json, createdAt
Benefit       id, userId, type(pro_50|pro_free_month), source(signup|referral|milestone_12|admin),
              referralId?, status(available|reserved|used|expired|revoked),
              issuedAt, expiresAt, usedAt, paymentId?
ChargeIntent  paymentId(unique), userId, plan, listAmount, discountAmount, expectedAmount,
              benefitIds Json, status(pending|paid|failed), createdAt
```
- `partner_code_seq` 시퀀스 1235 시작, 대표 1234 수동, 100~999 예약. 백필 SQL 1건(대표 Supabase 실행).

### 8.2 API
- `GET /api/partner/lookup?code=` 마스킹 이름(레이트리밋).
- `POST /api/partner/join {code}` 참여 확정: 조건 검사(7일/기존 회원/1회/순환/500명) → Referral + Benefit 2장 + partnerRank → 이메일.
- `GET /api/partner/me` 코드·순위·초대 현황·혜택 목록·다음 결제 예상.
- `/api/register` body에 `partnerCode?` 추가 → 가입 직후 join 로직 호출.
- 어드민: `POST /api/admin/partner/{grant|revoke|approve-milestone|assign-code}`(관리자 이메일 화이트리스트).
- 초대 가입자의 첫 인증(publish 성공) 시 Referral.firstProofAt 기록 → 유효 초대 카운트. 12명 도달 시 운영자 이메일 알림 → 어드민 `approve-milestone`으로 Benefit(pro_free_month ×6) 발급.

### 8.3 결제 반영 지점
- `subscriptionGrant.ts`: `chargeWithBillingKeyAndGrant`에 **혜택 적용 단계** 추가 — advisory lock 안에서 Benefit 예약(reserved) → expectedAmount 계산 → 0원이면 PortOne 호출 생략 → 성공 시 used, 실패 시 available 복원. `ChargeIntent`로 webhook/complete의 `amount_mismatch` 검증 대체. `planFromAmount`에 4,950 추가.
- `billing-key` 라우트(최초 구독): 첫 결제 2장 규칙(계정당 1회 플래그).
- `cron/charge-subscriptions`·`renew_now`: 1장 규칙.
- `refund.ts`: 실결제액 기준(이미 `i.amount` 사용 → ChargeIntent.expectedAmount 연결), 전액 환불 시 Benefit 복원.
- `GET /api/billing/subscription`: `nextChargeAmount`, `benefitsToApply` 추가 → 프로필·모달 표시.

### 8.4 UI
- 웹: 가입 폼 입력란·확인, 가입 완료 화면, 환영 모달(1회), 프로필 파트너 카드, checkout 금액 표시, 랜딩 `/partner`, FAQ 1문항, 약관·개인정보처리방침 문구, 이메일 템플릿 3종. i18n ko/en.
- 앱: 설정 탭 '파트너' 행(코드·복사·공유·입력, 금액 문구 없음). 다음 빌드 탑승.
