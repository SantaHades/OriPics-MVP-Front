## 0. 한 줄 요약

**사진함 패스(₩9,900)** = 사진함 1곳에서 1명이 사진 100장을 찍을 수 있는 이용권. 인증·공개링크·인증서가 포함되고, 5년 보관된다.
첫 적용처는 **부동산사진함**이다. 개설자(Pro)와 초대받은 참여자가 각자 패스 1장(또는 Pro 50% 할인권 2장)을 내고 들어온다. 개설자는 참여자 몫을 대신 낼 수 있다.

## 2. 핵심 개념: "좌석(seat)"

패스는 **(사진함, 사람)** 한 쌍에 묶인다. 이 묶음을 좌석이라 부른다.

- 좌석 = 그 사진함에서 그 사람이 쓸 수 있는 장수의 합.
- 패스를 더 등록하면 같은 좌석에 100장이 더해진다(누적 가능).
- 할인권 2장으로 들어오면 패스 1장과 똑같이 100장이다. 내부적으로 `source=coupon`인 패스 행을 만들어 동일하게 처리한다.
- 나가면 좌석이 **정지**되고, 재참여하면 그대로 **복구**된다. 좌석은 삭제되지 않는다.
- 부동산사진함에서 찍는 사진은 **항상 본인 좌석에서 차감**된다. 현행 일반사진함의 "개설자 부담(capture_billing=owner)" 규칙은 부동산사진함에 적용하지 않는다. 대납은 촬영 비용이 아니라 **좌석 비용**을 개설자가 내는 것이다.

## 4. 흐름별 규칙

### 4.1 부동산사진함 개설
1. 개설 화면에서 종류 선택. 부동산만 선택 가능, 나머지 3종은 "준비 중" 표시.
2. 개설자가 **Pro인지 확인**. 아니면 개설 버튼 비활성 + "부동산사진함은 Pro 회원만 개설할 수 있습니다".
3. 결제 수단 선택: ①보유한 미등록 사진함 패스 ②패스 코드 입력 ③Pro 50% 할인권 2장(사용 가능 상태만, 만료가 가까운 것부터).
4. 서버 트랜잭션에서 사진함 생성 + 개설자 좌석 바인딩을 한 번에 처리. 수단이 없으면 409 `seat_payment_required`.
5. 비밀번호 참여 필드는 부동산사진함에서 받지 않는다(초대 전용).

### 4.2 초대 (개설자)
- 초대 생성 시 **"참여 비용을 제가 냅니다"** 토글.
  - 켜면 개설자의 패스 1장(또는 할인권 2장)을 **예약**한다. 부족하면 토글 불가 + 안내.
  - 끄면 참여자가 수락할 때 본인이 낸다.
- 절반 대납 옵션은 만들지 않는다.
- 초대 유효기간은 현행대로 7일. 만료·취소 시 예약한 패스는 개설자에게 되돌아간다.
- 이전 멤버를 다시 부르는 초대는 자동으로 `is_rejoin`이 되고, 비용 토글이 숨겨진다.

### 4.3 초대 수락 (참여자)
- 대납 초대: "개설자가 이미 참여 비용을 냈습니다. 바로 참여할 수 있어요." 안내 → 수락하면 예약 패스가 참여자 좌석에 묶인다.
- 본인 부담 초대: 보유 패스, 코드 입력, 할인권 2장 중 선택. 없으면:
  - **앱**: "사진함 패스가 필요합니다. 보유한 패스 코드를 입력해 주세요." + 코드 입력칸. 링크·가격 없음.
  - **웹**: 같은 안내 + "사진함 패스 구매" 링크(/pass/photobox).
- 재참여 초대: 차감 없이 좌석 복구.
- Free 회원도 수락할 수 있다. 사진함 인원 한도는 개설자 기준(Pro 50명).

### 4.4 촬영·등록 차감
| 상황 | 차감 |
|---|---|
| 사진함 모드 촬영 | 본인 좌석 1장. 사이즈 무관, 공개링크 비용(−2) 없음, 인증서 무료 |
| 목록 사진 등록 (잔여 있음) | 본인 좌석 1장 |
| 목록 사진 등록 (소진 후) | 일반 크레딧 차감 (§9-5 금액 확인) |
| 촬영 (소진 후) | 불가. 안내: 패스 추가·코드 입력·목록 사진 등록 |
| 인증 실패·재시도 | 차감 없음. 서버 확정 시점에만 1장 (A-100 멱등과 같은 기준) |

- 원데이 패스는 부동산사진함 안에서 쓰지 않는다. 사진함 패스는 일반사진함에서 쓰지 않는다.
- 목록 사진 등록 화면에는 고정 문구: "사진목록의 사진을 사진함에 등록할 때도 1장씩 차감됩니다. 꼭 필요한 사진만 등록해 주세요."

### 4.5 소진 안내 (대납받은 멤버 포함 동일)
"이 사진함에서 쓸 수 있는 사진을 모두 사용했습니다. 사진함 패스를 추가하거나(코드 입력), 사진목록의 사진을 등록할 수 있습니다(일반 이용 건수 차감)."
웹에서만 구매 링크를 덧붙인다.

### 4.6 나가기·강퇴·재참여
- 나가기: 좌석 정지, 잔여 보존. 확인창 문구에 "나가면 남은 장수를 쓸 수 없고, 다시 초대받아 참여하면 복구됩니다. 환불되지 않습니다."
- 재참여는 초대로만 가능(초대 전용 사진함).
- 강퇴: 좌석 정지(§9-6 확인).

### 4.7 권한 이전
- 받는 사람이 Pro가 아니면 이전 버튼 비활성.
- 이전 후 원 개설자는 일반 멤버로 남고 좌석도 그대로 유지된다.

### 4.8 개설자 Pro 해지 후
- 사진 보관 5년, 멤버 촬영(각자 좌석)은 그대로 유지.
- **새 초대·대납·권한 이전은 Pro 재가입 전까지 불가**(§9-4 확인).

## 5. 구매·환불 (웹 전용)

- 페이지: `/pass/photobox`(상품 설명), `/pass/photobox/checkout`. 기존 `/pass`에는 두 상품을 나란히 둔다.
- PortOne 일회성 결제. 상품 마커 `photobox_pass`, 금액 검증 9,900원. `passPurchase.ts`의 검증·멱등 로직을 재사용한다.
- 결제 전 필수 동의 체크박스:
  - "사진함 패스는 사진함 1곳 전용이며 다른 사진함에서 사용할 수 없습니다."
  - "사진함에 등록(사용 시작)한 뒤에는 남은 장수가 환불되지 않습니다. 사진함에서 나가거나 사진함이 삭제된 경우에도 같습니다."
  - "등록하지 않은 코드는 구매 후 7일 이내 전액 환불됩니다."
- 환불: 미등록(`issued`) 코드는 7일 내 원클릭 환불(PortOne 취소 → `refunded`). 웹훅 취소 시에도 미등록분만 자동 회수(현행 원데이와 동일).
- 표기: "사진함 1개 전용 촬영 이용권(100장)". "충전·적립·포인트" 표현 금지(PG 심사 이력).
- 코드 사용 제한: 구매자 본인만 등록 가능(원데이와 동일). 선물 기능은 범위 밖.
- 판매 개시 조건: **U-44(카드사 서브몰 등록) 해소 후**. 원데이 패스와 같은 게이트.

## 6. 보관 5년 · 삭제 · 탈퇴

| 이벤트 | 일반사진함(현행) | 부동산사진함(신규) |
|---|---|---|
| 개설자 "삭제" | 7일 예고 후 실제 삭제 | **보관 전환**(`archived_at`): 멤버 목록에서 사라지고, 새 사진·초대 불가. 사진·확인서·백업은 `retain_until`까지 유지 |
| 멤버 회원탈퇴 | 멤버십 삭제(사진은 사진함에 남음) | 동일 + 업로더 표기 "탈퇴한 회원" |
| 개설자 회원탈퇴 | owner NULL로 사진함 방치 | 자동 잠금(읽기 전용). 보관 규칙 동일 |
| 개설자 Pro 해지 | 해당 없음 | 5년 보관 유지 |
| 만료 | 없음 | `retain_until` 경과 후 크론이 사진·파일·확인서 삭제, 30일 전 멤버에게 알림 |

- 보관 기한은 사진별 등록 시각 +5년, 사진함의 `retain_until`은 그중 가장 늦은 값.
- 멤버는 보관 기간 중 언제든 웹에서 확인서 PDF와 백업을 받을 수 있다.
- 개인정보 처리방침에 "부동산사진함 사진·확인서: 등록일부터 5년 보관(분쟁 증빙 목적), 탈퇴 시 업로더 식별정보 가림" 추가(웹 `/privacy` 개정 + 스토어 개인정보 양식 확인).

## 7. 화면 (앱·웹 공통, 앱은 가격·링크 제외)

1. **사진함 개설**: 종류 선택 카드 5개(부동산만 활성, 나머지 "준비 중"). 부동산 선택 시 결제 수단 영역 + "Pro 전용" 배지.

5. **목록 사진 등록 피커**: 차감 안내 고정 문구 + 소진 시 크레딧 차감 경고.
6. **나가기 확인창**: §4.6 문구.
7. **확인서 PDF**: 참여자 표에 "참여 비용: 본인/개설자 대납" 열 추가(증빙 가치).
8. **설정 탭 패스 카드**: 보유 사진함 패스(미등록 코드 수, 코드 입력). 가격 없음.

### 조사 중 발견한 현행 문제 — ✅4건 모두 수정(2026-09-23, 설계 확정과 함께 선반영)

처리: ①`capture_pro`에 활성 원데이 패스 반영 ②다운그레이드 크론에서 사진함 사진 제외 + 데이터 정리 SQL `db_migrations/2026_09_23_a108_mailbox_expiry_fix.sql` ③정책 확정 — **Pro 기간 중엔 패스 사진도 무기한(재구독 규칙 유지), 해지 시 원래 1년 기한(발행 +365일)으로 복귀, 이미 지났으면 일반 유예 37일** ④발행 시 5GB 검사를 프로필 표시와 같은 `storageUsage`(차감 주체 귀속)로 통일.

원래 기록:
- 사진함 DTO의 `capture_pro`가 개설자 티어만 보고 **활성 원데이 패스를 무시**한다(`lib/mailboxes/server.ts:400-405`).
- Pro 다운그레이드 크론이 **사진함 사진의 expires_at까지 +37일로 설정**한다(`cron/charge-subscriptions/route.ts:71-76`). 정리 크론이 사진함 사진을 건너뛰어 지금은 삭제되지 않지만, 5년 보관 도입 전에 제외 조건을 넣어야 한다.
- Pro 재구독 시 만료 전 링크를 모두 영구로 바꿔 **원데이 패스 사진(1년 보관)까지 영구화**된다(`lib/payment/subscriptionGrant.ts:200-203`).
- 발행 시 5GB 한도 검사가 `links.user_id = 차감 주체`로만 합산해, 멤버가 개설자 부담으로 찍은 사진이 **개설자 한도 검사에서 빠진다**(`links/publish/route.ts:174`). 프로필 용량 표시(`lib/storage/usage.ts`)는 차감 주체 기준으로 제대로 합산하므로 표시와 차단 기준이 어긋난다. 사진함 패스 사진은 개인 용량에서 제외하는 것을 제안.

### 외부 선행 조건
- **U-44**: 카드사 서브몰 등록(실결제). 해소 전에는 관리자 발급 코드로만 테스트.
- **A-64**: SSL.com TSA 무료 한도 연 1만 건. 사진함 패스 100장 기준 **패스 100장 판매로 연 한도 소진**. 부동산사진함 출시 전 유료 전환 조건 확정 필요.
- 보관 비용: 3024×4032 원본 PNG 약 12MB → 좌석 1개(100장) 약 1.2GB, 5년 스토리지 약 2천 원. 판매가 대비 감당 가능.
