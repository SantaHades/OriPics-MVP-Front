## 3. 1단계 상세 설계

### 3.1 해시 원장 `ProofLedger` (신규 테이블)

인증(`/api/links/confirm`) 성공 시 1행을 기록합니다. **사진·썸네일·GPS 좌표는 저장하지 않습니다.**

```prisma
model ProofLedger {
  id            String   @id @default(cuid())   // 공개 검증 ID (receipt에 포함)
  userId        String?                          // 계정 삭제 시 SetNull — 원장은 존속(증명 지속)
  finalHash     String   @unique                 // 스탬프 검증 해시 (sign에서 계산된 final_hash)
  innerHash     String                           // 기기 계산 inner 픽셀 SHA-256
  fileSha256    String?  @unique                 // 최종 산출 파일 바이트 SHA-256 (다운로드본 그대로 대조)
  phash256      String?                          // 256비트 pHash (hex 64자)
  dhash64       String?                          // 64비트 dHash (hex 16자) — 오인 방지 2차 지문
  tier          String                           // standard | verified
  capturedAt    String                           // 스탬프 타임스탬프
  certifiedAt   DateTime @default(now())
  width         Int
  height        Int
  linkId        String?                          // 공개링크 생성 시 연결 (publish에서 갱신)
  batchId       String?                          // 머클 배치 (일 1회)
  leafIndex     Int?

  @@index([phash256])
  @@index([batchId])
  @@index([userId, certifiedAt])
}

model LedgerBatch {
  id          String   @id @default(cuid())
  day         String   @unique                   // YYYY-MM-DD (KST)
  merkleRoot  String
  leafCount   Int
  tsaToken    Bytes?                             // RFC 3161 응답 (SSL.com)
  tsaTime     DateTime?
  createdAt   DateTime @default(now())
}
```

- **개인정보**: 해시와 지문만으로는 사진을 복원할 수 없습니다. 계정을 삭제하면 `userId`를 지우고(SetNull) 원장 행은 남깁니다. 이미 공유된 증명이 계속 검증돼야 하기 때문입니다. 이 내용은 개인정보처리방침과 계정 삭제 페이지에 명시합니다. "삭제 시 데이터 전부 삭제" 문구와 충돌하므로 **처리방침 개정이 선행돼야 합니다.**
- **멱등성**: `finalHash` unique라서 confirm 재시도(A-100) 시 같은 행을 재사용합니다.

### 3.2 클라이언트 지문 계산 (웹·앱 공통)

스탬프된 최종 이미지 기준으로 계산해 `/api/links/confirm` 요청에 함께 보냅니다.

| 값 | 계산 | 비고 |
|---|---|---|
| `file_sha256` | 최종 PNG 바이트 SHA-256 | 다운로드한 파일 그대로 올리면 즉시 일치 |
| `phash256` | 흑백 → 64×64 축소 → DCT → 좌상단 16×16 → 중간값 비교 → 256비트 | 재압축·크기 변경에 강함 |
| `dhash64` | 흑백 → 9×8 축소 → 인접 픽셀 밝기 비교 → 64비트 | 2차 확인용 |

- 웹: `lib/oripics-stamp`에 `perceptual.ts`를 추가합니다(canvas 기반, 순수 TS).
- 앱: 같은 알고리즘을 TS로 공유합니다. 픽셀은 기존 스탬프 파이프라인에서 디코드한 버퍼를 재사용합니다.
- **웹·앱 결과가 완전히 같아야 합니다.** 같은 이미지에 대한 골든 테스트 벡터를 둡니다. 리사이즈 보간이 다르면 비트가 달라지므로, 축소는 라이브러리를 쓰지 않고 직접 구현합니다(박스 평균).
- 서버는 받은 지문을 신뢰할 수밖에 없습니다(이미지를 받지 않음). 그래서 pHash 결과는 **"후보 찾기"로만** 쓰고, 증명 판정은 SHA·스탬프·C2PA가 맡습니다.

### 3.3 일일 머클 배치 + TSA

- **Vercel Cron**이 매일 00:10 KST에 실행합니다. 전날 `batchId IS NULL`인 원장 행을 `certifiedAt` 순으로 정렬해 leaf로 씁니다. leaf는 `SHA-256(finalHash ‖ certifiedAt)`입니다.
- 머클 루트를 SSL.com TSA(RFC 3161)로 타임스탬프한 뒤 `LedgerBatch`에 저장합니다.
- 각 원장 행에 `batchId`와 `leafIndex`를 기록합니다. 증명 경로(proof path)는 조회할 때 재계산합니다. 하루 수천 건이면 비용이 무시할 수준입니다.
- 효과
  - 공개링크가 없는 인증도 **제3자 시각 증명**을 받습니다.
  - TSA 사용량이 연 365건으로 줄어 A-64(건당 원가) 문제가 사라집니다.
  - 공개링크의 장별 C2PA TSA는 현행대로 유지합니다(C2PA 표준 요구).
- 인증 직후부터 배치 전까지는 "시각 증명 대기(익일 확정)"로 표시합니다.

### 3.4 검증 무료화 (`/api/verify`)

| 변경 | 내용 |
|---|---|
| 로그인 | 불필요. 로그인 사용자는 본인 사진 표시 등 부가 정보만 받음 |
| 차감 | `VERIFY_QUERY` 폐지. 기존 크레딧 거래 기록은 보존 |
| 미공개 사진 | `not_published` 404 대신 **원장 조회로 검증 성공**. 공개링크가 없다는 사실만 표시 |
| 남용 방지 | IP 기준 레이트리밋(기존 `RateLimit` 테이블). 예: 분당 20회, 일 500회 |
| 응답 | 촬영·인증 시각, 등급, 머클 배치 시각(TSA), 공개링크 유무. 계정 정보는 내보내지 않음 |

**신규 조회 경로 `/api/verify/lookup`**: 스탬프가 손상된 사본용입니다.
- 입력: `file_sha256` 또는 `phash256`·`dhash64`. 브라우저에서 계산하고 사진은 업로드하지 않습니다.
- 판정 순서: ① `fileSha256` 정확 일치 → "인증 원본 그대로" ② pHash 해밍 거리 ≤ 40/256이면서 dHash ≤ 10/64 → "인증 원본의 사본(재압축·크기 변경)으로 보임 + 후보 정보" ③ 없으면 "오리픽스 인증 기록 없음"
- **정보량이 낮은 이미지**(단색·단순 패턴)는 "추적 정확도 낮음"으로 표시하고 단정하지 않습니다.
- 초기 검색: 원장이 수십만 행 수준이면 앱 서버에서 전수 비교해도 충분합니다(행당 32바이트). 수백만 행에 가까워지면 다중 색인 해싱이나 pgvector bit로 전환합니다.
- 문구 원칙: "일치합니다"는 SHA 또는 스탬프가 확인될 때만 씁니다. pHash 결과는 "시각적으로 유사한 인증 원본 후보"로 표현합니다.

### 3.5 화면 변경

- 홈 업로드 박스와 `/verify`: "자세히 확인(1크레딧)" → "무료 검증"으로 바꾸고 로그인 유도를 제거합니다.
- 검증 결과 카드에 다음을 추가합니다: 머클 시각 증명 상태, 사본 판정 안내, 다운로드 가능한 검증 기록(JSON 영수증).
- 가격 페이지, 요금 정책, 약관: 검증 무료를 반영합니다.
- 앱: 검증 기능 자체는 웹 링크로 연결합니다. 앱 쪽 변경은 confirm 요청에 지문 3종을 추가하는 것뿐입니다.

### 3.6 작업 순서

1. Prisma 마이그레이션(`ProofLedger`, `LedgerBatch`), 처리방침·계정 삭제 문구 개정안
2. `perceptual.ts`(pHash·dHash) + 골든 테스트 벡터(웹·앱 동일성)
3. confirm에서 원장 기록, publish에서 `linkId` 갱신
4. 머클 유틸 + cron + TSA 클라이언트(기존 SSL.com 연동 재사용)
5. `/api/verify` 무료·비로그인화 + `/api/verify/lookup`
6. 웹 UI·문구·요금 정책 문서 갱신 → 배포
7. 앱 confirm에 지문 추가 → 다음 빌드 탑승

**과거 인증분**: 원장 도입 전 인증은 해시가 없습니다. 공개링크가 있는 사진은 저장된 이미지에서 지문을 백필할 수 있습니다(1회 스크립트). 공개링크가 없는 사진은 현행 스탬프 검증만 가능합니다.

| 원가 | 머클 TSA로 장당 TSA 원가가 거의 0입니다. 남는 원가는 공개링크 Storage(Free 7일)뿐입니다 |

- 3단계 요청 응답 촬영은 Free라도 **Verified(앱 촬영)를 허용**하는 방안을 함께 검토합니다. 요청자 입장에서 신뢰의 핵심이 Verified이기 때문입니다.
- 50크레딧 이상은 권하지 않습니다. 패스 판매(일회성 대량 수요)와 겹치기 때문입니다.
