# 사서함 v2 UX 기획 — "관련자끼리 사진을 공유하는 공동 사서함"

작성 2026-09-09 · **v0.3**(대표 답변 14건 + 추가 지시 5건 반영, §11 구현 산정 포함)

## 0. 현재 상태와 바뀌는 것

| 항목 | 현재(빌드 15) | v2 |
|---|---|---|
| 사서함 성격 | 운영자가 SQL로 등재한 **수신함**. 사진을 기기 메일 앱으로 첨부 전송 | **누구나 개설**하는 공동 사진 공간. 사진은 서버 공개링크로 저장, 참여자 앱에서 열람 |
| 위치 | 제출 탭 세그먼트 [이벤트·사서함·제보], 기본=이벤트 | 세그먼트 유지, **순서 [사서함·이벤트·제보]로 변경, 제출 탭 첫 화면=사서함** |
| 참여 | 이름/번호+비밀번호로 '내 목록에 추가' | 이름+비밀번호 **또는 1회용 초대코드**(이름·역할·촬영 조건 지정). 참여자 목록·열람 현황 관리 |
| 사진 넣기 | 갤러리 피커 → 메일 첨부 | ①촬영하기(촬영 탭과 동일, **좌표·공개링크 포함 자동 인증**, 건수는 참여자별 설정: 개설자(기본)/본인) ②사진 제출하기(목록 탭의 **인증 완료 사진만**) |
| 사진 보존 | 소유자가 링크 삭제 가능 | 사서함 소속 링크는 **사서함 삭제 전 삭제 불가**, 사서함에서 빼기(철회·숨김)도 **전면 금지** |
| 열람 확인 | 없음 | 사진별 **미열람 참여자 수**(카톡식, 0도 표기) |
| 보존 | 기기 로컬 이력 JSON | 참여자 누구나 **웹 저장소로 백업**(백업 시각 표시), 확인서 PDF(무료), 삭제 예고 → **7일 유예** |
| 초대 제어 | visibility public/private | **초대 진행 중 / 초대 종료** 토글(명칭 변경, §5) |
| 기존 샘플 | 오류신고·사용사례 사서함(메일 전송) | **오류신고 삭제**, **사용사례는 설정 탭으로 이동**(메일 전송 방식 유지, §8) |

재사용: `mailboxes`·`user_mailboxes`·`join_mailbox`, `ChannelJoinModal`, 촬영 탭(`capture.tsx`)·인증 파이프라인(`certify.ts`→`/api/sign`·`/api/links/publish`), 전체화면 뷰어(A-80), 인증서 PDF 렌더러(`@oripics/certificate`), 웹 프로필 보관함, 공개 메모(A-76).

## 1. 용어

- **개설자(owner)**: 사서함을 만든 사람. 설정 화면, 삭제·잠금, 참여자 관리, 기본 촬영 건수 부담.
- **참여자(member)**: 초대를 수락해 참여 중인 사람. 열람·촬영(허용 시)·제출·백업·PDF·나가기.
- **초대 대기자(invitee)**: 초대코드가 발급됐지만 아직 수락하지 않은 사람.
- **역할(role)**: 개설자가 자유 입력하는 문구(예: 발주자, 임차인, 중개인, 렌터카 직원, 고객). 선택 라벨 아님.
- **사서함 사진**: 사서함에 올라간 사진 1장 = 공개링크(`links`) 1건 + 사서함 소속 정보 + 열람 기록.
- **열람(read)**: 참여자가 그 사진의 **상세 화면(전체화면 뷰어)을 연 것**. 썸네일 노출은 열람이 아님.
- **초대 진행 중 / 초대 종료**: 새 참여를 받는지 여부. 종료 상태에서는 코드 입력·비밀번호 참여 모두 차단.
- **사서함 잠금(읽기 전용)**: 공사 완료 등으로 더 이상 사진을 넣지 않는 보존 상태. 열람·백업·PDF만 가능.

## 2. 화면 지도

```
제출 탭 ─ 세그먼트 [●사서함 | 이벤트 | 제보]   ← 순서 변경, 기본=사서함
            │
            └ S1 사서함 홈(🔔 알림) ──┬─ S2 사서함 개설(+ 추가하기, 나의 사서함)
                                     ├─ S3 사서함 참여(+ 추가하기, 초대받은 사서함)
                                     └─ S4 사서함 자세히 보기
                                           ├─ S5 사진 상세(뷰어 + 속성 + 열람 현황)
                                           ├─ S6 사서함 촬영(촬영 탭 동일)
                                           ├─ S7 사진 제출하기(목록 탭 인증 사진 선택)
                                           ├─ S8 사서함 설정(개설자만) ─ S9 초대코드 생성 ─ S9b 초대문 보기(복사·QR·공유)
                                           └─ ⋯ 메뉴: 백업 / 확인서 PDF / 사서함 정보 / 나가기(참여자) / 잠금·삭제(개설자, S10)
설정 탭 ─ '사용사례 보내기' 카드(기존 사용사례 사서함 이관, 메일 전송)
웹(ori.pics) ─ /invite/<코드> W4 초대 랜딩(QR·링크 착지: 앱 열기 / 설치 / 코드 표시)
웹(ori.pics) ─ 프로필 > 사서함 ──┬─ W1 백업 목록
                                ├─ W2 백업 상세(사진·참여자·확인서 PDF·영구삭제)
                                └─ W3 참여 중 사서함 실시간 열람(2차)
```

```
┌─────────────────────────────────────┐
│ 사진 제출                        🔔2 │

│                                     │
│ 나의 사서함                     ↻    │
│ ┌─────────────────────────────────┐ │
│ │ 용인 ○○빌라 302호 리모델링  초대 종료│ │
│ │ 철거~마감 전 과정 기록. 발주자·… │ │
│ │ 사진 42 · 미열람 3      [자세히 보기]│ │
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ + 추가하기 (사서함 개설)          │ │
│ └─────────────────────────────────┘ │
│                                     │
│ 초대받은 사서함                      │
│ ┌─────────────────────────────────┐ │
│ │ 스타렌트 12허3456 인수·반납   🔒잠금│ │
│ │ 개설자 김○○(스타렌트)            │ │
│ │ 사진 8 · 미열람 0       [자세히 보기]│ │
│ └─────────────────────────────────┘ │
│ ┌─────────────────────────────────┐ │
│ │ + 추가하기 (초대코드 / 이름+비밀번호)│ │
│ └─────────────────────────────────┘ │

```

- **세그먼트 순서 [사서함·이벤트·제보], 기본 선택=사서함**(대표 확정). `report.tsx`의 `SEGMENTS` 순서와 초기 state만 바꾸면 된다.
- **두 목록 순서**: 내가 책임지는 것(나의 사서함)이 위, 남이 부른 것(초대받은)이 아래.
- **카드**: 제목 · 설명문 1~2줄 · `사진 N · 미열람 M` · [자세히 보기]. M = **내가 아직 안 본 사진 수**, 0이면 '미열람 0' 명시. 초대받은 카드에는 개설자 이름 한 줄 추가.
- **[자세히 보기] 명시 버튼**: 카드 탭도 열리지만, 처음 쓰는 임차인·고객이 "여기를 누른다"를 알 수 있게 버튼을 둔다.
- **[+ 추가하기]가 두 목록 각각 제일 아래**: 위=개설, 아래=참여. 목록 끝에 두어 "이 목록에 하나 더"라는 의미.
- **상태 배지**: `초대 종료`(새 참여 차단) · `🔒잠금`(읽기 전용) · `⚠️N일 후 삭제`(붉은 띠, [지금 백업]). 내보내진 사서함은 목록에서 사라지고 알림만 남는다.
- **🔔 알림 센터**(우상단): 인앱 알림 목록(§6). 미확인 수 배지.
- **빈 상태**: 나의 사서함 없음 → "공사·임대·렌터카 관련자와 사진을 공유하는 사서함을 만들어 보세요" + [+ 추가하기]. 초대받은 사서함 없음 → "초대코드를 받았다면 여기서 입력하세요".
- **한도(대표 확정)**: 무료 사용자 개설 1개·참여자 20명, Pro 개설 무제한·참여자 50명. 한도 도달 시 [+ 추가하기]/초대코드 생성에 안내("Pro에서 더 많은 사서함·참여자").
- 기존 메일 전송 이력 화면은 제거.

```
┌ ‹ 사서함 개설 ───────────────────────┐
│ 사서함 이름*        [                ] │
│ 설명문 (참여자 모두에게 보임)          │
│   [                                 ] │
│ 초대            (● 진행 중  ○ 종료)     │

│ 초대 비밀번호 (선택)  [        ] 👁    │
│   비밀번호를 두면 이름+비밀번호로도 참여  │
│ 사서함 메모 (나에게만 보임)             │
```

- 최소 입력은 **이름 하나**. 나머지는 S8에서 언제든 변경.
- 만든 직후 **S8 설정으로 이동해 초대코드 생성을 바로 유도**(개설 목적이 초대).
- 이름은 **내 계정 안에서 중복 금지**, 시스템 전체에서는 허용(이름+비밀번호 참여 시 복수 매칭이면 개설자 이름을 함께 보여 고르게 함). 서버 번호(MB-xxxx) 유지, S8에 표시.

### S3 사서함 참여 (초대받은 사서함 [+ 추가하기])

```
┌ 사서함 참여 ─────────────────────────┐
│ [● 초대코드]  [○ QR 스캔]  [○ 이름+비밀번호]│
│                                     │
│ 초대코드     [ A7K3-9QXZ ]             │
│              또는 [📷 QR 스캔하기]      │
│                                     │
│ ── 코드 확인 후 ──                     │
│ 사서함   용인 ○○빌라 302호 리모델링     │
│ 개설자   박○○(○○인테리어)             │
│ 내 이름  이△△ (개설자가 지정, 수정 불가) │
│ 역할     임차인                        │
│ 촬영     허용 · 건수는 개설자 부담        │
│ 이 이름·역할로 참여자 목록·확인서에 표시됩니다│
│                                     │
│        [취소]   [참여하기]              │
└─────────────────────────────────────┘
```

- 기존 `ChannelJoinModal`(번호/이름 토글)을 **초대코드 / QR 스캔 / 이름+비밀번호** 3단 토글로 개편.
- **QR 스캔**(대표 제안 채택): 원데이 패스 카드의 QR 스캐너(`day-pass-card.tsx`, expo-camera CameraView)를 재사용. QR에 담긴 초대 URL(`https://ori.pics/ko/invite/A7K3-9QXZ`)에서 코드를 추출해 초대코드 입력과 동일한 미리보기로 이어진다. 스캔 즉시 참여시키지 않고 **미리보기 → [참여하기]**를 거치게 해 잘못 스캔한 QR로 들어가는 일을 막는다.
- 카톡·문자로 받은 초대문의 **링크를 탭한 경우**: 앱이 설치돼 있으면 `oripics://invite/<코드>`로 앱이 열려 S3 미리보기까지 자동 진행. 미설치면 W4 랜딩(§4)에서 설치 안내와 코드를 보여 준다.
- **코드 입력 → 서버 조회 → 미리보기 → [참여하기]**. 개설자 지정 이름·역할은 회색 읽기 전용(요청: 수정 불가). 잘못된 사서함 진입을 막고 "내 이름이 이렇게 기록된다"를 알린다.
- 이름+비밀번호 경로에는 지정 이름이 없으므로 **참여자가 표시 이름을 직접 입력**(필수), 역할은 비움. 개설자가 S8에서 편집.
- 실패 메시지: 코드 없음 / 이미 사용된 코드 / 코드 만료 / **"초대가 종료되어 참여할 수 없는 사서함입니다. 개설자에게 문의하세요"** / 내보내진 참여자(개설자에게 해제 요청) / 참여자 한도 초과 / 로그인 필요(설정 탭 로그인으로 안내).

### S4 사서함 자세히 보기

```
┌ ‹ 용인 ○○빌라 302호 리모델링   ⚙  ⋯ ┐   ⚙=개설자만 / ⋯=모두
│ 철거~마감 전 과정 기록. 발주자·임대인·   │
│ 시공팀이 함께 확인합니다.               │
│                                     │
│ 참여자 4  ▸                          │
│ 박○○(개설자) · 이△△(임차인) · 최□□(중개인) · 정◇◇
│                                     │
│ 사진 42            [사진 제출하기] [📷 촬영하기]
│ ┌────┐┌────┐┌────┐                  │
│ │ 🅽  ││    ││ 🅽  │  🅽 = 내가 미열람   │
│ │ 👁2 ││ 👁0 ││ 👁4 │  👁N = 미열람 참여자 수│
│ └────┘└────┘└────┘                  │
│ …(무한 스크롤, 최신 위)                │
└─────────────────────────────────────┘
```

- **제목·설명문·참여자·사진이 한 스크롤**. 참여자 행은 `이름(역할)`을 나열, ▸ 탭 시 전체 목록 시트(이름·역할·수락 시각·상태). 개설자 설정의 참여 중 목록과 **같은 데이터**를 읽기 전용으로 보여 준다(요청). 자기 행에만 '촬영 건수: 개설자/본인'이 보인다.
- **[사진 제출하기] [촬영하기]가 사진 목록 우측 상단**. 촬영 권한 꺼진 참여자는 회색 + "개설자가 촬영을 허용하지 않은 참여자입니다". 개설자 부담 참여자는 개설자 건수 부족 시 "개설자의 인증 건수가 부족합니다"(개설자에게 알림), 본인 부담이면 기존 402 안내. 잠금 상태면 두 버튼 모두 숨김 + "잠긴 사서함입니다(읽기 전용)".
- **썸네일 배지 두 종류**: 🅽=내 기준 미열람, 👁N=사서함 기준 미열람 인원(**0도 표기**).
- **⋯ 메뉴(모두)**: 웹 저장소로 백업 · 확인서 PDF 받기 · 사서함 정보(번호·개설일·개설자·한도) · **나가기**(참여자만) · 잠금/잠금 해제·삭제(개설자만).
- **나가기(대표 확정)**: 확인창 "나가면 이 사서함이 목록에서 사라집니다. 내가 올린 사진은 사서함에 그대로 남습니다" → 참여자 목록에 '나감' 표기, 개설자에게 알림. 다시 들어오려면 새 초대코드 필요.
- 삭제 예고 중이면 최상단 붉은 띠 "개설자가 삭제를 예고했습니다. YYYY-MM-DD HH:mm 삭제 → [지금 백업]".

### S5 사진 상세

```
┌ ✕                                   ┐
│          [ 전체화면 사진 ]             │  A-80 뷰어(핀치·이동)
│ 올린 사람  이△△(임차인) · 2026-09-09 14:02 촬영
│ 좌표 37.2411, 127.1776 (지도 열기)     │
│ 공개링크 ori.pics/ko/AB12… [복사] [공유] │
│ 열람  3/4 · 미열람 1  ▸ (정◇◇)         │
│ 공개 메모  "주방 배관 교체 전"  [편집: 올린 사람만]
└─────────────────────────────────────┘
```

- **열면 열람 기록**(서버 `read` upsert). 뒤로 나가면 S4 배지 즉시 갱신. 열람 행 ▸ = 참여자별 열람 시각 목록(PDF와 동일 출처).
- 속성은 기존 공개링크 뷰어 데이터 재사용(촬영시각·좌표·등급·공개링크).
- **캡션 = 기존 공개 메모(A-76, 100자) 재사용**(대표 확정). 별도 코멘트 없음.
- **삭제·철회·숨김 버튼 없음**(대표 확정: 전면 금지). 사서함 소속 링크는 사서함 삭제 전까지 어디서도(목록 탭·웹 뷰어·프로필 히스토리) 삭제 불가. 시도 시 팝업 **"사서함 '○○'에 포함된 사진이라 삭제할 수 없습니다. 사서함을 먼저 삭제해야 합니다."**(복수 사서함이면 모두 나열). 서버 DELETE `/api/links/:id`는 409 `in_mailbox`.

### S6 사서함 촬영 ([촬영하기])

- **촬영 탭 화면 그대로**, `mailboxId` 파라미터로 진입. 상단 배너 **"📮 ○○에 촬영 중 · 개설자 건수 사용"** 또는 본인 부담이면 **"… · 내 건수 사용 (잔여 27)"**. 인증마크·줌 동작 동일.
- **좌표(GPS)·공개링크 기본 포함·해제 불가**(요청). GPS pill·링크 토글은 켬 고정으로 잠금 표시. 위치 권한 없음/fix 대기 중이면 "사서함 촬영은 좌표가 필요합니다" 안내 후 fix 확보 시 셔터 활성. 인증마크 ON/OFF는 촬영자 선택.
- 셔터 후 **자동 인증·발행**(원데이 패스 자동 모드와 동일), **사서함 전용 큐**에만 저장 → 목록 탭에 나타나지 않음(요청).
- **차감 주체 = 참여자별 설정**(기본 개설자, S8). 서버가 `mailbox_id` 컨텍스트로 `capture_billing`을 읽어 개설자 또는 촬영자 계정(원데이 패스 포함)에서 차감. 개설자 본인 촬영은 항상 개설자. 등급은 차감 주체 티어(Pro=Verified).
- 사진 1장 = 인증(Standard 3 / Verified 4 × 크기 배수) + 링크 2.
- 오프라인·서버 실패 시 그리드에 "업로드 대기" 회색 카드, 다음 진입 시 재시도. 실패는 촬영자에게만 표시.

### S7 사진 제출하기 ([사진 제출하기])

- 목록 탭에서 **인증(발행) 완료된 사진만** 다중 선택(대표 확정: 미인증 불허). 이벤트 출품 선택과 동일 패턴(썸네일 탭=크게 보기, 행 탭=선택) → [N장 제출] → 링크 재사용, **추가 차감 없음**.
- 미인증 사진은 회색 + "먼저 목록 탭에서 인증하세요". 공개링크 없이 인증된 사진도 제외(사서함 사진은 공개링크 필수).
- 같은 링크 재제출은 "이미 제출된 사진 N장 제외" 안내.
- 제출과 동시에 그 링크는 **삭제 잠금** 대상이 된다 — 제출 확인창에 "제출한 사진은 사서함이 삭제되기 전까지 삭제할 수 없습니다" 명시.

- **사서함 잠금(읽기 전용)**(대표 확정): 촬영·제출·초대 잠김, 열람·백업·PDF 가능. 카드 배지 🔒잠금, 전원 알림. 개설자가 언제든 해제. 삭제와 달리 데이터가 남는 '보존 종료'.

- 안내문은 **서버 템플릿**(ko/en)으로 만들어 앱·웹이 같은 문구를 쓴다. 개설자 이름·사서함 이름·초대받는 이름·역할·만료일·코드·URL을 치환. 개설자가 문구를 직접 고치는 기능은 두지 않는다(코드·만료일 누락 방지).
- 코드가 이미 사용·만료·무효화됐으면 이 화면 상단에 상태 띠("이미 참여했습니다 9/10 14:02" / "만료됨 — 새 코드를 만드세요")를 보이고 복사·공유 버튼은 비활성.

### 알림 센터 (S1 우상단 🔔, 인앱)

- **1차 인앱, 2차 이메일**(대표 확정). 푸시(expo-notifications)는 3차 후보.
- 앱 실행·제출 탭 진입 시 서버에서 미확인 알림 조회 → 🔔 배지. 항목 탭 시 해당 사서함으로 이동.
- 2차 이메일: 삭제 예고·내보내기·건수 부담 변경 등 **행동이 필요한 알림만** 메일로도 발송(새 사진 알림은 인앱만, 스팸 방지).

## 4. 웹 화면

### W1 사서함 백업 목록 (프로필 > 사서함)

| 열 | 내용 |
|---|---|
| 사서함 | 이름 · 개설자 · 내 역할(개설자/참여자·역할 문구) |
| **백업 시각** | 2026-09-09 16:40 · 사진 42장 · 참여자 4명 |
| 용량 | 118 MB (**백업한 사람의 보관함 5 GB에 포함**, 대표 확정) |
| 동작 | [열기] [확인서 PDF] [영구삭제] |

- **백업 = 그 시점 스냅샷**, 횟수 무제한, 시점별 행이 쌓인다. 스냅샷은 메타·참여자·열람 상태를 복제하고 사진 파일은 참조만 해 용량을 아낀다. **삭제 예고 상태에서 만든 백업은 사진 파일까지 백업자 보관함으로 복사**(사서함 삭제 후에도 사진 보존).
- **백업 시각은 W1·W2·PDF 머리말·앱 완료 토스트("16:40 백업본이 웹 저장소에 저장되었습니다") 네 곳에 표시**(요청).
- [영구삭제]: 확인 문구 입력 후 즉시, 복구 불가(요청).
- **백업·PDF 모두 건수 차감 없음**(대표 확정).

### W2 백업 상세

- 상단: 이름·설명문·개설자·개설일·**백업 시각**·참여자 표(이름·역할·수락 시각·상태).
- 사진 그리드: 썸네일 · 촬영시각 · 좌표 · 올린 사람(역할) · 공개링크 · 열람 N/M(백업 시점). 썸네일 탭=라이트박스(ZoomableImage).
- [확인서 PDF 내려받기] [영구삭제].

### W4 초대 랜딩 `ori.pics/{ko,en}/invite/<코드>` (1차, QR·링크 착지)

- 로그인 불필요. 표시: 사서함 이름 · 개설자 · 초대받는 이름(역할) · 만료일 · **[앱에서 열기]**(`oripics://invite/<코드>`) · **[앱 설치]**(App Store / Play, OS 자동 판별) · 코드 큰 글씨 + [복사].
- 코드 상태(유효/사용됨/만료/초대 종료)를 서버에서 조회해 문구를 바꾼다. 사서함 사진·참여자 목록 등 내용은 **절대 노출하지 않는다**(코드만으로 열람 불가).
- 앱 설치 직후 첫 실행에서 코드가 유실되는 문제(iOS 딥링크 미보존)는 W4가 코드를 크게 보여 주고 복사 버튼을 두는 것으로 흡수한다. Universal Links(AASA)는 현재 미설정이라 커스텀 스킴만 사용, 2차에 검토.

### W3 참여 중 사서함 실시간 열람 (2차, 대표 확정)

- 프로필 > 사서함에 '참여 중' 탭 추가. 앱 S4와 같은 정보(현재 상태)를 웹에서 열람·백업·PDF. 웹에서 열어도 열람 기록. 촬영은 앱 전용, 제출은 웹 히스토리에서 선택 가능하게(2차 범위에서 결정).

### 11.5 위험·결정 포인트
| 위험 | 대응 |
|---|---|
| **타인 계정 차감**(개설자 부담): 참여자 요청으로 개설자 크레딧 소비 | 서버가 `mailbox_members` 권한(can_capture·kicked·locked·delete_after)과 `capture_billing`을 매 요청 검증, 기존 `consumeCredits` 원자성 사용, `CreditTransaction.memo`에 사서함·촬영자 기록 → 웹 크레딧 내역에서 개설자가 확인 가능 |
